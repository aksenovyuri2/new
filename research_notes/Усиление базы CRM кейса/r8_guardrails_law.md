## Q1. Право РФ: рассылки, согласие, штрафы, маркировка (подвопрос 4.3)

### Takeaway
Для email, push и SMS рекламная рассылка в РФ допустима только с предварительным согласием, доказывать его обязан отправитель; штраф для юрлица по КоАП 14.3 ч. 4.1 — 300 тыс. – 1 млн руб. Для SMS действует отдельный режим 126-ФЗ ст. 44.1 (договор с оператором, отказ абонента через оператора с прекращением на следующий календарный день). Маркировка ЕРИР/erid по официальной позиции РКН не требуется для email и push; для SMS прямого официального заявления не найдено.

### Inferences
- Для платформы это значит: реестр согласий (дата, текст, источник, канал, версия) — обязательная зависимость MVP, потому что бремя доказывания лежит на отправителе по трём независимым нормам (ст. 18 38-ФЗ, ст. 44.1 126-ФЗ, ст. 9 152-ФЗ).
- Опт-аут SMS через оператора сам по себе не доходит до платформы: если абонент отказался у оператора, SMS «не доставлено» без нашего события. Отсюда guardrail: доля недоставленных SMS по причине «отказ у оператора» нужно получать из отчётов агрегатора (вывод; в источниках не описано, как агрегаторы возвращают такой статус).
- Штраф за один эпизод рассылки без согласия ограничен, но повторяется на каждое обращение гражданина; для сети вертикалей одно нарушение одной вертикали создаёт риск для юрлица в целом (вывод).

### Gaps
- Номера дел и тексты решений ФАС 2024–2026 не найдены в первичном виде (fas.gov.ru недоступен из этой среды).
- Дата вступления в силу п. 1.1 ст. 44.1 в тексте 41-ФЗ не проверена (дата 01.08.2025 / 01.09.2025 подтверждена только для постановления № 1137).
- Вывод «ЕРИР не нужен для SMS по своей базе» официально не найден: письмо РКН и постановление № 1427 говорят про email и push. Вторичные источники (Unisender, vc.ru, smsdar) утверждают, что SMS по собственной базе не маркируют, но первичного подтверждения нет.
- Содержание будущих редакций (ст. 18 38-ФЗ; ФЗ № 210-ФЗ от 26.06.2026 с 01.03.2027) не читалось.

## Q2. Каналы РФ: push (RuStore), SMS (имя отправителя и цены), MAX, WhatsApp/Telegram (подвопрос 4.3)

### Takeaway
Push через RuStore имеет официальную документацию и API, задуманный как замена Firebase. Для SMS нужны отдельные имена у каждого оператора с абонплатой 2 080–3 000 руб./мес (Т2 — бесплатно для рекламных), а цена SMS растёт ступенчато по числу сообщений одному абоненту в месяц. MAX по официальным требованиям не допускает рекламных и массовых рассылок через API без отдельного договора. WhatsApp фактически заблокирован (домены исключены из НСДИ), Telegram ограничен; опираться на них как на критический канал нельзя.

## Q3. Guardrail-пороги и нормы с числами (подвопрос 2.3)

### Takeaway
Для email есть три слоя порогов: внешние (Gmail/Yahoo: цель жалоб 0,1%, жёсткий предел 0,3% — из прошлого отчёта), отраслевые из документации российских ESP (жалобы 0,1–0,2%, отписки менее 1%, недоставки менее 2%) и методика остановки/решения в экспериментах (Spotify: guardrail как тест не хуже допуска, без поправки на множественность; Eppo: порог «вреда» по нижней границе интервала). Для push и SMS внешних числовых порогов нет; есть правила платформ (Apple 4.5.4, Android 13) и юридический срок исполнения отказа в SMS (следующий календарный день). Числа остановки экспериментов компании по-прежнему не публикуют.

### Cited Findings
- Google и Yahoo: целевой спам-рейт ниже 0,10%, жёсткий предел 0,30% (Gmail, массовые отправители 5000+ писем в сутки) — [Google, ред. 2026](https://support.google.com/a/answer/81126) и [Yahoo Sender Hub](https://senders.yahooinc.com/best-practices/) (из прошлого отчёта, повторно не открывались).
- Altcraft (российский ESP), таблица «здоровой рассылки»: доставляемость выше 98%, недоставки ниже 2%, открытия выше 20%, клики выше 10%, жалобы ниже 0,2%, отписки ниже 1%; hard bounce не более 1%; если доставляемость падает ниже 85%, почтовые серверы предлагают очистить базу — [Altcraft, «Показатели здоровья email»](https://altcraft.com/ru/help-center/analitika/pokazateli-zdorovya-email).
- Mindbox: spam rate — отношение жалоб к доставленным, допустимо не более 0,2%; доставляемость оценивают по проценту доставок, попаданий в спам, отписок и жалоб; рекомендуется еженедельный разбор, отчёт «Здоровье email» — [Mindbox, «Аналитика email-рассылок»](https://mindbox.ru/journal/education/email-analitika/).
- Unisender: «если количество жалоб превысит 0,1%, то следующую рассылку могут заблокировать полностью»; жалоба хуже отписки, потому что бьёт по репутации — [Unisender, «Базовые показатели»](https://www.unisender.com/ru/blog/bazovye-metriki/). Расхождение порогов: Unisender 0,1%, Altcraft и Mindbox 0,2%, Google жёсткий предел 0,3% — для guardrail брать самый строгий (0,1%) как красную линию домена.
- Apple App Review Guidelines 4.5.4: push не должны быть обязательны для работы приложения; не использовать push для промо и прямого маркетинга, если пользователь не дал явного согласия через текст в интерфейсе приложения и нет способа отказаться в приложении; злоупотребление может привести к отзыву привилегий. 4.5.3: нельзя использовать Apple-сервисы, включая push, для спама и нежелательных сообщений — [Apple, App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/).
- Android 13 (API 33) и выше: разрешение POST_NOTIFICATIONS выдаётся в рантайме; для только что установленного приложения уведомления выключены по умолчанию; запрашивать разрешение нужно в контексте, после того как пользователь понял ценность — [Android Developers, notification permission](https://developer.android.com/develop/ui/views/notifications/notification-permission) (цитаты получены через сводку WebFetch).
- Полевой эксперимент (17 500 пользователей мобильных приложений ритейла, пять частот push, семь недель): при росте частоты неперсонализированных push растут удаления приложения и падает direct open rate; значимого влияния на indirect opens не доказано — Wohllebe, Hübner, Radtke, Podruzsik, Innovative Marketing 17(2), 2021, DOI 10.21511/im.17(2).2021.10 (метаданные из Crossref; полный текст с числами не читался) — [ResearchGate](https://www.researchgate.net/publication/351932011_Mobile_apps_in_retail_Effect_of_push_notification_frequency_on_app_user_behavior). Это рецензируемое подтверждение направления «частота → удаления», числовых порогов в аннотации нет.
- Spotify (статья 02.2024 и пост 03.2024): метрики делятся на success (тест превосходства), guardrail (тест «не хуже допуска», non-inferiority margin, NIM), deterioration (тест ухудшения) и quality; правило решения: все guardrail не хуже допуска, нет признаков ухудшения, есть хотя бы одна улучшившаяся метрика; поправка уровня значимости на множественность для guardrail не нужна, но мощность корректируется как β/(G+1), где G — число guardrail — [arXiv 2402.11609](https://arxiv.org/abs/2402.11609) (формула проверена в PDF) и [Spotify Engineering, 03.2024](https://engineering.atspotify.com/2024/03/risk-aware-product-decisions-in-a-b-tests-with-multiple-metrics). NIM — «допустимый уровень ухудшения» задаётся самой командой; конкретные значения для уведомлений не опубликованы.
- Eppo (документация): guardrail cutoff — пороговое значение вреда, задаваемое для метрики; предупреждение («жёлтое») появляется, когда нижняя граница доверительного интервала выходит за порог; рекомендация — подумать об отказе от раскатки варианта — [Eppo Docs, Guardrail cutoffs](https://docs.geteppo.com/data-management/organizing-metrics/guardrails/). Statsig: метрические алерты с порогом и минимальным числом единиц эксперимента — [Statsig, Metric Alerts](https://www.statsig.com/updates/update/metric-alerts) (по выдаче поиска; страница не открывалась); определение guardrail как «страховки» — [Statsig blog](https://www.statsig.com/blog/what-are-guardrail-metrics-in-ab-tests).
- Для SMS юридический «SLA» отказа: прекращение рассылки в течение следующего календарного дня после заявления абонента (п. 219 Правил, постановление № 1137) — [Гарант](https://www.garant.ru/products/ipo/prime/doc/412324200/).
- Яндекс: официальная страница о проблемах с отправкой писем говорит, что при жалобах на рассылку отправителю приходит уведомление «поступили жалобы на рассылку спама с вашего адреса», но числового порога в тексте нет — [Яндекс 360, проблемы с отправкой](https://yandex.ru/support/yandex-360/customers/mail/ru/web/letter/create/troubleshooting).

### Inferences
- Набор guardrail для кейса: (1) жалобы на спам по домену (красная линия 0,1%, по Unisender и Google-цели), (2) отписки на доставленные письма (менее 1%, Altcraft), (3) недоставки (менее 2%, hard bounce не более 1%), (4) opt-in и отключение push по ОС, удаления приложения, (5) для SMS — стоимость на абонента в месяц и доля отказов у оператора, (6) долгосрочная метрика против holdout (Spotify-логика).
- Решающее правило для тестов можно взять у Spotify: «все guardrail не хуже допуска» с допуском, зафиксированным до теста; допуск придётся задавать по собственному базовому уровню (в открытых источниках значений нет).
- Числа вроде «1 push в неделю — 10% отключают» остаются без первоисточника; полевой эксперимент Wohllebe даёт только направление, поэтому в ответе на кейс использовать их как качественный довод, а не как порог.

### Gaps
- Числовых порогов остановки эксперимента у компаний не найдено (ни у Spotify, ни у Eppo/Statsig в документации — только механизм).
- Нет первичных российских данных по SMS opt-out и по удалению приложений из-за уведомлений; Airship (из прошлого отчёта) остаётся единственным числовым бенчмарком для push.
- Числовой порог жалоб Яндекса не найден; порог Mail.ru из прошлого отчёта (Mindbox/Mailfit) остаётся неофициальным.
- Даты публикации таблиц Altcraft, Mindbox и Unisender на страницах не указаны; это вендорские ориентиры, а не регуляторные нормы.
