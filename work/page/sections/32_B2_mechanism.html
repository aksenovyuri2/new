В первой версии шлюз только запрещает; оценивать он начнёт после квартала данных

Отправщик перед каждой отправкой спрашивает шлюз. Шлюз проходит шесть проверок и отвечает за {{b1_gate_ms|num0}} мс: разрешено, отложено или отказ. Всё записывается в журнал. Оценка пользы и формула — вторая версия.

Псевдокод первой версии

def gate(person, msg, now):                    # ответ за {{b1_gate_ms|num0}} мс
    if msg.cls == "service":       return allow(msg)   # код, сделка, ответ продавца
    if person in EXCLUSIONS[msg.cls]:  return deny("исключение")
        # отписка, жалоба, нет согласия; диалог с продавцом и сделка — только для промо
    if msg.cls == "promo" and person in CONTROL:  return deny("контроль")
    if over_limit(person, person.stage, msg.cls):  # промо {{limit_push_day|num0}} в сутки и {{limit_week|num0}} в неделю,
        return wait_or_deny(msg)                    # подписки {{b1_sub_cap_day|num0}} в сутки; новичку и «поиск закончен» — без промо
    if quiet_hours(person.search_tz, now) or quiet_hours(person.device_tz, now):
        return wait_or_deny(msg, until=morning, ttl_hours={{b1_ttl_hours|num0}})
    if same_event_seen(person, msg, hours={{b1_dedup_hours|num0}}):  return deny("дубль")
    return allow(msg)           # любой исход пишется в журнал
# режим журнала, пока вертикаль не включена: ответ всегда allow, исход пишется
# сбой шлюза: промо не уходит, сервисные уходят

Ответ на вопрос кейса

  • Кому. Человеку, которого нет в списке исключений и в контрольной группе. Аудиторию выбирает заказчик, шлюз её только проверяет.
  • Что. Сервисное идёт всегда. Подписки идут под своим потолком. Промо идёт в пределах общего лимита; побеждает быстрая полоса, затем более свежее событие.
  • В каком канале и когда. По схеме Б3: в продукте — место внутри, не в продукте и срочно — пуш, иначе письмо; ночью ждёт утра.
  • «Не отправлять» — полноправный исход. У каждого отказа есть причина, и отправщик её видит.
  • Оценка пользы, бюджет отписок и порог по сегменту — вторая версия, после квартала данных. Решение «свой слой или российский вендор» принимаем на 6-й неделе по двум предложениям.
  • Включение по шагам. Ключи пуша за шлюзом к {{b4_w_keys|num0}}-й неделе, почты — к 12-й. Сначала режим журнала: для ещё не включённых вертикалей шлюз отвечает «разрешено» и только пишет. Запрет включается по вертикалям, первая — к 3-му месяцу. Частота по стадии поиска: новичку и «поиск закончен» — без промо, в паузе — одно промо в 7 дней Допущение.

Откуда это

  • Практика рынка Порядок «допуск, лимит, оценка» одинаков у Adobe и в собственных системах Авито и Pinterest. Авито: из четырёх кампаний при лимите три проходят три лучшие. ЦентрКредит и iFood называют умение промолчать частью продукта.
  • ЦИАН, открытые данные Время отправки пушей ЦИАН уже подбирает алгоритмом, как именно — неизвестно. Есть ли у ЦИАН общий лимит и журнал, тоже неизвестно: если есть, первая версия сжимается до контрольной группы. Выясняем в первые три недели.
  • Предложение Шесть проверок в таком порядке; ответ за {{b1_gate_ms|num0}} мс; ключи провайдеров за шлюзом к {{b1_week_keys|num0}}-й неделе; список контроля у всех отправщиков с {{b1_week_holdout|num0}}-й недели.
  • Допущение Лимит промо, потолок подписок, тихие часы, срок жизни отложенного сообщения. Значения подбираем по журналу и тестам.
