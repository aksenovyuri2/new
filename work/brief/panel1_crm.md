# Панель 1: Head of CRM

## Оценки 1–5
| Ось | Оценка | Почему |
|---|---|---|
| Стратегия и деньги | 4 | Честно: платформа даёт ~13% разрыва, остальное защита канала. |
| Экономика и кейс | 3 | Нет стоимости постройки и владения. |
| Механизм решения | 3 | Формула это v2; для v1 нет классов, исключений, холодного старта, in-app. |
| Измерение | 4 | Три слоя КГ сильны, но holdout не работает при обходе шлюза. |
| Мандат и оргмодель | 3 | «Жёсткий блок» без рычага принуждения. |
| Реализуемость MVP | 2 | В 90 дней: опись, журнал, лимит, КГ, согласия, 3 провайдера, прогрев почты. |

## Три блокера

**1. v1 противоречит себе: «модели потом», а в Б2 полная формула; не сказано, как шлюз встаёт перед отправкой.**
Вставить: «v1 = синхронный pre-send API (suppress, holdout, общий лимит, классы, тихие часы, дедуп), без скоринга; ответ до 100 мс; при падении промо fail-closed, сервисные fail-open. Ключи ESP и push-провайдеров переносим за шлюз к неделе 8: без вызова шлюза отправить нельзя. Журнал по доставке. v2 (мес. 4–9): uplift, бюджет отписок, адаптивный порог. Б2 помечена «целевая v2»; нулевая версия (лимит без оценки) идёт в первый замер».

**2. Нет классов сообщений, исключений и внутренних мест.**
Алерты по сохранённым поискам: серая зона 38-ФЗ. Баннеры, placements, stories в решении отсутствуют.
Вставить: «Классы: T0 сервисные (код, сделка, ответ продавца), вне лимита и КГ; T1 подписки (алерты), свой потолок, статус фиксируют юристы до MVP; P промо, под лимитом и КГ. Исключения единым списком: отписки, жалобы, нет согласия, активный диалог с продавцом или сделка 7 дней, сотрудники. Внутренние места: показ это запрос, не отправка; в v1 шлюз считает показы в журнале (1 показ = 0,1 контакта, вес утверждает совет), в v2 слот-аукцион на тех же весах и планках. Иначе команды уйдут в баннеры».

**3. Доставка и сроки: критический путь не влезает в 90 дней.**
Прогрев почты 8–12 недель, согласия, три провайдера пуша; SMS-откат (R2-0317) вынесен из MVP, доставка пуша 20–40% ниже отчётной. Цель «14% → 5%» считается по всей базе при 60% сценариев вне шлюза.
Вставить: «Неделя 1: старт прогрева двух ESP, замер доставки пуша, запрос предложений у 2 российских вендоров, юристы отдельным потоком. Шлюз сглаживает выпуск по доменам. Неделя 6: gate «build или гибрид». 3 месяца: 1 вертикаль на полном шлюзе, остальные через suppress/holdout-API; цель 3+ промо по журналу всех отправителей. 6 месяцев: 3–4 вертикали, большинство к 9–12».

## Замечания
1. **Д2, КГ на неделе 4, шлюз на 3–6** → КГ вне шлюза не соблюдается → suppress-API к неделе 3.
2. **Холодный старт** → нет в записке → дефолтная частота по стадии, welcome-серия вне скоринга, 1% случайных с первого дня, uplift после N контактов.
3. **Тихие часы** → 11 поясов → пояс по региону поиска и устройству; defer с TTL, иначе deny; сервисные исключены.
4. **Б3 каскад** → недоставленный пуш молча теряется → считать «доставлено», откат пуш→почта, SMS пилотом.
5. **Д2, опись опросом** → у 60% сценариев нет владельцев → автоопись по логам ESP и push.
6. **Г1** → нет санкции за обход → паспорт сценария обязателен, иначе deny.
7. **Д1, build/buy без числа** → вилка: 6–8 разработчиков, аналитик, PM; журнал и КГ свои, отправку не строить.
8. **В2, единый ID** → гость с push-токеном → хэш по устройству и аккаунту; долю достижимых замерить за 2 недели как гейт.
9. **SLO шлюза** → задержка, доля fail-open, расхождение журнала с провайдерами <3%.

## Что сильно
- Честная арифметика кейса: 13% разрыва, три сценария, цена КГ.
- Три слоя контроля; бюджет отписок вместо штрафа в формуле.
- Профессионалы в v1 только сигнал и защитная метрика.
