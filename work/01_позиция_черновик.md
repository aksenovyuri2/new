# Этап 1. Черновик позиции

Написан до разбора исследования и до досбора. Исследование должно его подтвердить или сломать. Финальная версия — на остановке после 14 решений.

## 1. Тезис

**Рабочая версия:** платформа управляет не рассылками, а вниманием человека. Внимание — общий ограниченный бюджет компании. Контакт тратится только там, где он даёт доказанный прирост. Если прироста нет, лучшее решение — промолчать.

| Гипотеза | Что должно подтвердиться в исследовании | Итог |
|---|---|---|
| Т1. Внимание — общий бюджет, им распоряжается одна точка | Крупные компании ставят общий лимит на человека в одном месте, а не в командах | |
| Т2. Лучшее сообщение часто — никакое | Есть измеренные случаи: объём вниз, а результат не хуже | |
| Т3. Спор за аудиторию решают правила и измерение | Есть работающие правила приоритета и общая контрольная группа; ручные комитеты — исключение | |
| Т4. В недвижимости решение принимается для пары «человек и его поиск» | У площадок недвижимости поиск эпизодичен и конец поиска меняет коммуникацию | |

## 2. Что значит «привлечение»

**Рабочая версия:** платформа привлекает не трафик, а следующий шаг. Три задачи:

1. Довести нового человека до первого целевого действия: сохранённый поиск, первый контакт с продавцом.
2. Вернуть человека к новому поиску, когда у него появилась потребность.
3. Привести человека из одной вертикали в соседнюю: арендатор → покупатель, покупатель → ипотека, покупатель → собственник с объявлением.

Платная реклама вне продукта остаётся у маркетинга. Платформа делит с ней профиль, список «кому не показывать» и общую контрольную группу.

Почему так: пуш и письмо не приводят человека без аккаунта и согласия.

## 3. Охват платформы

| Что | В охвате? | Почему |
|---|---|---|
| Ищущие и собственники | Да, с первой версии | Это 20 млн из задания |
| Агенты, агентства, застройщики | Учёт да, решение нет | У них свой кабинет и менеджеры. Но их письма и пуши идут в общий счётчик |
| Сервисные сообщения: код, статус, безопасность | Проходят через платформу, но не ограничиваются и не спорят | Нужны в общем счётчике давления |
| Сообщения от другого человека: чат, звонок | То же | Их ждут |
| Оповещение о новом объявлении по сохранённому поиску | Отдельный класс: человек сам попросил | Скорость здесь часть продукта |

## 4. Единица решения

**Человек и его текущий поиск.** Один человек может одновременно искать аренду и продавать квартиру. Это два поиска с разными сигналами и разной усталостью от темы, но с одним общим лимитом внимания.

У поиска есть состояния: начал, активно ищет, остывает, закончил, между сделками. Успех поиска означает, что человек уходит. Поэтому «удержание» здесь — три разные задачи: удержать в окне поиска, не сжечь канал до следующего поиска, вернуть к новой потребности.

## 5. Единица ценности

**Ожидаемый добавленный целевой контакт, взвешенный по ценности для компании.** Целевой контакт: звонок, чат, заявка застройщику, заявка на ипотеку, размещение объявления.

Слабое место: заявка застройщику стоит на порядки дороже звонка по аренде. Если сравнивать только в рублях, дорогая вертикаль выигрывает всегда. Как закрываем:

- ценность сравнивается внутри класса приоритета, а не по всей базе;
- у каждой вертикали есть гарантированная доля внимания в неделю;
- небольшой бюджет на пробы для новых сценариев без истории;
- заявленная ценность сверяется с фактом из контрольной группы.

## 6. Скелет формулы

```
оценка = шанс действия × добавленная доля × ценность действия × уместность
         − штраф за усталость − шанс отписки × цена потерянного канала
```

Отправляем, только если оценка выше порога. Иначе молчим.

| Число | Откуда в первой версии |
|---|---|
| Шанс действия | Историческая конверсия по типу сообщения и сегменту |
| Добавленная доля | Сначала таблица по типам сообщений, потом замер из контрольной группы. Для уже активных за три дня — понижающий коэффициент: в задании на них приходится 60% действий |
| Ценность действия | Таблица по вертикалям, которую утверждает не заказчик, а платформа вместе с финансами |
| Уместность | Совпадение с текущим поиском и его состоянием: да, частично, нет |
| Штраф за усталость | Ступени по числу контактов за 7 дней |
| Шанс отписки | 0,25% на пуш из задания, выше для уставших |
| Цена потерянного канала | Сколько целевых контактов в год приносит один достижимый человек |

## 7. Граница MVP

**Допущение:** общий номер человека есть для вошедших в аккаунт, а единого профиля со всеми событиями нет. В задании только 40% сценариев идут через общий инструмент.

Следствие: первая версия не может опираться на личные модели. Она опирается на общий журнал контактов, общий лимит на точке отправки, правила приоритета и общую контрольную группу.

## 8. Спорные решения

| Решение | От чего отказываемся | Цена |
|---|---|---|
| Общая контрольная группа 5% базы не получает промо вообще | Оставить контроль только на уровне кампаний | Часть выручки в коротком сроке. Спор с вертикалями |
| Общий лимит с первого дня для всех, включая самые доходные вертикали. Доли внимания вместо чистого сравнения в рублях | Аукцион по ожидаемой выручке | Доходная вертикаль недополучит контактов |
| «Не отправлять» — исход по умолчанию. Плановые объёмы рассылок командам не гарантируются | Планирование от охвата | Команды теряют привычный рычаг выполнения плана |
| Сначала учёт, лимит и замер. Модели потом | Начать с умного подбора сообщений | Первая версия выглядит простой |

## 9. Четыре разночтения в цифрах: рабочие трактовки

| Разночтение | Рабочая трактовка | Что из неё следует |
|---|---|---|
| 14% с тремя промо в сутки — от кого? | От получателей за сутки. От недельной аудитории быть не может: нужно 23,5 млн отправок в неделю, а их 12 млн | В сутки сообщения получают не больше 1,34 млн человек. На 14% из них приходится минимум треть суточного объёма |
| Сколько из 12 млн — пуши? | Половина | Около 15 тыс. отписок от пушей в неделю, 780 тыс. в год |
| Входят ли в 12 млн показы внутри продукта? | Нет, только отправки | Реальное давление выше, чем 1,5 контакта на человека в неделю |
| Как пересекаются 30% кампаний без контроля и 40% сценариев через общий инструмент? | Независимо | И под общими правилами, и с честным замером — не больше 28% запусков |
